## 교육·테스트용 설치와 실행

Python 3.10 이상에서 격리된 교육·테스트 목적으로만 실행하세요. 운영 서비스 사용에는 별도 서면 허가가 필요합니다. Windows PowerShell 기준:

```powershell
git clone https://github.com/Nikuyi-cnst/Suro-DiscordApp.git
Set-Location Suro-DiscordApp
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

로컬 `.env`에 `DISCORD_TOKEN`, `GITHUB_TOKEN`, `GITHUB_REPOSITORY=Nikuyi-cnst/Suro-DiscordApp`을 설정하세요. `DISCORD_CHANNEL_ID`는 정기 알림용 선택 설정입니다. 실제 토큰은 예제 파일이나 Git에 넣지 마세요. 직접 주입한 환경변수는 `.env`보다 우선합니다.

```powershell
.\.venv\Scripts\python.exe Index.py
```

Discord의 **Message Content Intent**를 활성화하고 `bot`, `applications.commands` 권한으로 초대하세요. 기존 관리자·알림 환경변수도 계속 사용할 수 있습니다.

## `/문의` 사용법과 공개 범위

`/문의 content:문의 내용`으로 접수합니다. **이미지 첨부는 선택 사항**이며, 첨부할 때는 이미지 파일만 허용합니다. 공백만 있는 내용은 접수하지 않으며, 앞뒤 공백을 제거한 후 최대 1,000자입니다.

명령을 제출하면 다음 항목이 **공개 GitHub 이슈**로 등록됩니다.

- 문의 내용
- 작성자의 Discord 표시 이름
- 이미지를 첨부한 경우 해당 이미지 링크

공개 이슈에는 Discord 사용자 ID, 서버 이름, 서버 ID를 별도 정보로 추가하지 않습니다. 다만 사용자가 내용/이미지에 직접 포함한 정보와 이미지 URL 자체의 식별 정보는 공개됩니다. **개인정보, 비밀번호, 봇 토큰 등 비밀 정보는 보내지 마세요.** 비공개 문의 전용 기능은 없습니다.

기존 **개발자 DM 전달도 유지**하며, 같은 문의를 GitHub 공개 이슈에도 등록합니다. 개발자 DM에는 기존처럼 문의 내용, Discord 사용자명과 사용자 ID, 서버 이름과 서버 ID를 전달하며 선택 이미지는 파일로 첨부합니다. DM이 차단되면 `ADMIN_CHANNEL_ID`로 지정한 관리자 채널에 대신 전송합니다. 해당 채널의 열람 권한은 운영자가 제한해야 합니다.

두 경로는 동시에 독립적으로 시도합니다. DM 실패나 첨부 다운로드 실패 때문에 GitHub 등록을 생략하지 않으며, GitHub 설정 오류나 등록 실패가 발생해도 DM은 시도합니다. DM 경로는 60초 내 완료되지 않으면 결과 확인 불가로 안내합니다. 개발자 전달 경로는 기존 코드의 `DEVELOPER_USER_ID`를 사용하고, 관리자는 선택적으로 `.env`에 `ADMIN_CHANNEL_ID=채널ID`를 설정할 수 있습니다.

응답에는 GitHub 등록 결과와 개발자 전달 결과(DM 또는 관리자 채널)를 각각 표시합니다. 한쪽만 성공해도 전체 성공으로 표시하지 않습니다. 성공한 GitHub 이슈 링크도 명령 사용자에게만 안내합니다. 봇 응답이 비공개여도 **GitHub 이슈 자체는 누구나 볼 수 있습니다.**
고로 `/문의`를 사용한다는것은 **GitHub에 올라온 이슈에 있는 모든 내용은 모든 사람에게 공계를 해도 된다**로 간주합니다.

이미지를 GitHub에 별도 업로드하지 않고 Discord 첨부 링크를 기록하므로, 링크가 만료되거나 원본이 삭제되면 이미지가 표시되지 않을 수 있습니다. 영구 보관이 필요하면 민감 정보를 확인한 뒤 관리자가 GitHub 이슈에서 직접 첨부하세요.

연결 오류로 생성 여부를 확인하지 못하면 재접수 전에 Issues 목록을 확인하세요. 중복 이슈 방지를 위해 봇은 생성 요청을 자동 재시도하지 않습니다. DM은 차단 시 관리자 채널로 대체 전송할 뿐 일반 오류나 타임아웃을 자동 재시도하지 않습니다. 한쪽만 실패하여 명령을 다시 제출하면 이미 성공한 쪽에 중복 전달될 수 있습니다. GitHub 등록에는 성공했지만 Discord 응답 전달이 실패한 경우에도 먼저 Issues를 확인하세요.

## 버전 복원 안내

이전 버전의 로컬 소스 백업에서 다음 순서로 코드 상태를 복원했습니다.

| Release 이름 | 코드 태그 |
|---|---|
| GA1.0-S (Restored) | `GA1.0-S` |
| GA1.1-S (Restored) | `GA1.1-S` |
| GA1.2-S (Restored) | `GA1.2-S` |
| GA1.3-S (Restored) | `GA1.3-S` |
| OB2.0-U.E (Restored) | `OB2.0-U.E` |

Release의 제목은 왼쪽 이름 그대로입니다. 오른쪽 태그는 GitHub가 Release의 기준 코드를 가리키는 별도 식별자입니다.

기존 Git 기록이나 과거 출시일을 재현한 것이 아닌 **소스 스냅샷 복원**입니다. 과거 코드에는 최신 문의 연동을 소급 적용하지 않았습니다. Releases에서 **Source code (zip)**을 내려받아 해당 시점의 코드를 확인할 수 있습니다. 실행하려면 각 버전의 의존성과 별도 로컬 환경 설정이 필요합니다.

최신 `GA2.0-S`는 별도 최신 원본에서 가져온 개발 코드입니다. GA2.0-S 자체와 이후 문의 연동은 커밋으로만 관리하며, GA2.0-S 태그나 Release는 만들지 않습니다.

원본 실행 폴더와 백업은 수정하지 않습니다. 따라서 이미 실행 중인 봇에는 이 변경이 자동 적용되지 않습니다. 새 코드는 별도 폴더에서 격리된 교육·테스트 목적으로만 실행하세요. 운영 서비스로 전환하려면 저작권자의 별도 사전 서면 허가가 필요합니다. 허가된 환경에서 DB를 옮길 경우 봇을 중지하고 로컬에서 별도로 백업·이전하며, Git에는 올리지 마세요.

## 비밀 파일 보호

모든 복원 커밋과 릴리즈를 포함해 `.env` 및 환경별 변형, 기존 `.git` 기록, DB, 로그, 가상환경, 캐시는 업로드하지 않습니다. `.env.example`은 비밀값 없는 설정 예제만 제공합니다.

`.gitignore`는 **이미 추적된 파일이나 과거 기록에서 비밀을 제거하지는 않습니다.** 이전 저장소 등에 토큰이 커밋된 적이 있다면 Discord Developer Portal에서 봇 토큰을 재발급하고, GitHub 토큰도 폐기·재발급하세요. 새 저장소로 옮겼다고 과거 노출이 해소되는 것은 아닙니다. 이 이전 작업은 기존 저장소의 기록을 수정하거나 저장소를 삭제하지 않습니다.

커밋 전에 아래 명령으로 파일 목록을 확인하세요. 실제 토큰이 들어 있는 파일을 `git add -f`로 강제로 추가하지 마세요.

```powershell
git status --short
git ls-files
git check-ignore .env
```

## GitHub에서 자주 쓰는 용어

| 용어 | 뜻 |
|---|---|
| 저장소 / Repository | 코드, 변경 기록, 문의 이슈를 모아두는 프로젝트 공간 |
| 커밋 / Commit | 특정 시점의 코드 변경을 저장한 기록 |
| 브랜치 / Branch | 다른 코드에 바로 영향을 주지 않고 작업하는 갈래. `main`은 기본 코드 |
| PR / Pull Request | 브랜치의 변경을 검토하고 합치기 위한 요청 |
| 병합 / Merge | 작업한 변경을 다른 브랜치에 합치는 것 |
| 이슈 / Issue | 버그, 질문, 기능 요청을 기록하고 논의하는 게시글 |
| 태그 / Tag | 특정 커밋에 붙이는 고정 버전 이름 |
| 릴리즈 / Release | 태그의 코드에 설명과 다운로드를 붙이는 배포 페이지 |
| Clone | 저장소와 기록을 내 컴퓨터에 처음 복사하기 |
| Push / Pull | 로컬 커밋을 GitHub에 올리기 / GitHub 변경을 로컬로 가져와 합치기 |
| `.gitignore` | Git에 새로 추가하지 않을 파일과 폴더를 지정하는 목록 |
